## CS 230 Portfolio Reflection

### Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room was the client for this course. They wanted to expand their Android game, *Draw It or Lose It*, so it could support multiple platforms and users. The software needed to allow multiple games, teams, and players to run at the same time while remaining secure, scalable, and reliable.

### What did you do particularly well in developing this documentation?

I think I did well comparing different operating platforms and explaining why certain technologies would work better for the client. I also became more comfortable looking at factors such as memory, storage, security, networking, and scalability instead of only focusing on the code itself.

### What about the process of working through a design document did you find helpful when developing the code?

The design document helped me organize the requirements before jumping directly into development. Breaking the system into smaller sections made it easier to understand how the different parts of the application would work together and what problems might need to be addressed before coding.

### If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

I would improve some of my earlier explanations of the different operating platforms. After completing the course, I have a better understanding of Linux, Windows, macOS, mobile systems, and cloud environments. I could now provide stronger comparisons and explain the advantages and disadvantages in more detail.

### How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?

I focused on The Gaming Room's need to support multiple players and platforms while keeping the game responsive and secure. That influenced my recommendation of a Linux-based server environment with web-based clients so users could access the game from different devices. Considering user needs is important because even well-written software will not be successful if it does not solve the actual problems or provide a good experience for the people using it.

### How did you approach designing software? What techniques or strategies would you use in the future?

I approached the design by first identifying the requirements and then comparing possible solutions for the operating system, storage, memory, networking, security, and distributed architecture. In the future, I would continue using design documents, UML diagrams, requirements analysis, and platform comparisons before beginning development. This course helped me realize that planning the architecture first can prevent problems and make the development process much more organized.
